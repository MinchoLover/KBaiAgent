# 심사용 비밀정보 전달 원칙

## 전달 경로

- 실제 `judge-demo.env`는 공개 GitHub와 Git history에 포함하지 않습니다.
- 공개 저장소에는 값이 비어 있는 `.env.example`과
  `judge-demo.env.example`만 둡니다.
- 실제 파일은 공모전의 비공개 파일 제출 경로 또는 접근자가 제한된 암호화 전달
  수단으로만 제공합니다.
- 키 문자열을 기술설명서, 발표자료, 보고서 PDF, 화면 캡처 또는 메신저 본문에
  붙여 넣지 않습니다.

## 발급 원칙

- 공모전 심사용으로만 발급한 임시 키를 사용합니다.
- 개인·운영·다른 프로젝트의 키와 분리합니다.
- 가능한 경우 사용량·도메인·IP·기간 제한과 예산 상한을 설정합니다.
- 실제 고객 문서가 아닌 저장소의 합성 문서만 live 확인에 사용합니다.
- 심사 종료 직후 발급기관에서 키를 폐기하고 로컬 파일을 삭제합니다.

## 제출 전 체크

- [ ] `judge-demo.env`의 빈 키 슬롯에 심사용 임시 키만 입력했다.
- [ ] `git check-ignore -v judge-demo.env .env`에서 두 파일이 ignored로 나온다.
- [ ] `git ls-files .env judge-demo.env` 출력이 비어 있다.
- [ ] 공개 ZIP, PPT, PDF, 스크린샷에 키가 없다.
- [ ] Golden Demo는 키와 네트워크 없이도 완주한다.
- [ ] 비공개 팩과 공개 저장소의 commit 식별자를 함께 기록했다.

## 심사 후 폐기 목록

- [ ] OpenAI 심사용 임시 키
- [ ] 한국수출입은행 환율 API 키 또는 심사용 분리 자격증명
- [ ] 관세청 공공데이터 API 키 또는 심사용 분리 자격증명
- [ ] 로컬 `.env`
- [ ] 로컬 `judge-demo.env`
- [ ] 비공개 팩 ZIP과 압축 해제본
- [ ] 심사 중 생성한 민감 다운로드 파일

키 폐기는 외부 서비스의 관리화면에서 사용자가 직접 수행합니다. 프로젝트 코드가
키를 자동 폐기하거나 외부 계정을 변경하지 않습니다.
