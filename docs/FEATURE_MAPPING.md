# Feature Mapping

## 상태 기준

- **KEEP**: 현재 구현을 그대로 유지
- **EXTEND**: 기존 구현에 최소 기능 추가
- **ADD**: 신규 구현 필요
- **LATER**: 공모전 제출 이후로 보류

---

## 1. 문서 입력과 거래 확정

| 기능 | 상태 | 현재 구현 | 이번 작업 | 완료 기준 |
|---|---|---|---|---|
| 무역문서 업로드 | KEEP | PDF·이미지 검증 및 문서 추출 | 기존 기능 유지 | 샘플 문서 정상 처리 |
| 거래정보 추출 | EXTEND | 당사자·국가·통화·금액·결제일 추출 | 결제방식·선지급 비율·신규 거래처·보호수단 추가 | 추출하거나 사용자가 수정 가능 |
| 사용자 확인 | EXTEND | 통화·금액·결제일 확인 | 핵심 결제조건도 확인 대상에 추가 | 확인 전 분석 실행 차단 |

관련 코드:

- `src/document_intake/`
- `src/domain/document_models.py`
- `src/document_intake/confirmation.py`
- `src/workflow/gates.py`

## 2. 위험 분석

| 기능 | 상태 | 현재 구현 | 이번 작업 | 완료 기준 |
|---|---|---|---|---|
| 환율 AI 분석 | EXTEND | 외부 Stage 1·수동 스트레스 지원 | `kb_macro_ai` 전용 어댑터 연결 | API 성공 시 모델 사용, 실패 시 fallback |
| 국가·무역환경 위험 | ADD | 없음 | 최소 국가·제도·무역 추세 신호 추가 | 위험 원인 2~3개 표시 |
| 계약·결제 위험 | ADD | 결제조건 추출만 존재 | 신규 거래처·선지급·장기 외상·보호수단 규칙 추가 | 점수·등급·근거 표시 |
| 환노출 계산 | KEEP | 보유외화·자연상계·기존 헤지 계산 | 기존 로직 유지 | 기존 테스트 유지 |
| 원화 현금흐름 | KEEP | 일별 잔액·현금 부족·신용한도 계산 | 핵심 결과를 UI에 명확히 표시 | 첫 부족일·최대 부족액 표시 |

관련 코드:

- `src/stage1/`
- `src/stage2/`
- `src/stage2/cashflow.py`
- `src/stage2/metrics.py`
